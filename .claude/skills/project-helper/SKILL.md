# project-helper — помощник по проекту «ЭкоЗадание»

Этот скилл применяется **только** в репозитории `product-description-generator`. Он даёт Claude Code постоянный контекст о структуре, стеке и соглашениях проекта, чтобы каждое изменение было осмысленным и согласованным с остальной кодовой базой.

## Когда вызывать

Используй этот скилл при ЛЮБОЙ работе в проекте:

- Запуск / перезапуск / остановка сервиса
- Добавление или правка фич (роуты, сервисы, шаблоны, промпты)
- Обновление `README.md` или другой документации
- Поиск и исправление ошибок
- Рефакторинг
- Подготовка к публикации (GitHub, упаковка, релиз)
- Любой вопрос «как устроено X в этом проекте»

## Стек и соглашения

- **Язык/версия:** Python 3.10+ (`from __future__ import annotations`, `str | None`)
- **Веб-фреймворк:** Flask 3 (фабрика приложения, Blueprint)
- **LLM:** локальный Ollama через `requests` (HTTP API на `http://127.0.0.1:11434`)
- **Схемы:** Pydantic (`app/models/schemas.py`)
- **Шаблоны:** Jinja2 в `app/templates/`
- **Стиль:** чистый CSS + JS, никаких фронтенд-сборщиков
- **Тесты:** `pytest`
- **Логирование:** стандартный `logging`, логгеры объявляются на уровне модуля
- **Комментарии/докстринги:** на русском, кратко и по делу
- **Имена файлов:** `snake_case`; **классы** — `PascalCase`; **функции/переменные** — `snake_case`
- **Импорты:** абсолютные внутри проекта (`from app.services...`, `from config.config import ...`)
- **Конфиги:** только через `config/config.py` и переменные окружения из `.env`

## Карта проекта (запоминай)

```
product-description-generator/
├── app.py                          # точка входа: create_app() + app.run()
├── requirements.txt                # Flask, python-dotenv, requests
├── .env.example                    # шаблон переменных окружения
├── README.md                       # публичная документация (обновлять!)
├── PROJECT_STRUCTURE.md            # подробная карта (если есть)
├── config/
│   └── config.py                   # Config / DevelopmentConfig / ProductionConfig
├── app/
│   ├── __init__.py                 # фабрика create_app()
│   ├── routes.py                   # Blueprint «main»: /, /create, /generate, /health
│   ├── services/
│   │   ├── llm_client.py           # HTTP-обёртка Ollama + LLMError
│   │   └── generator.py            # бизнес-логика generate_assignment()
│   ├── models/schemas.py           # GenerationRequest / GenerationResponse
│   ├── prompts/                    # шаблоны промптов для LLM
│   ├── templates/                  # Jinja2: index.html, form.html, result.html
│   └── static/                     # css/, js/, images/
└── tests/
    └── test_routes.py              # pytest
```

### Маршруты

- `GET /` — лендинг (`index.html`)
- `GET /create` — форма (`form.html`)
- `POST /generate` — генерация задания (`result.html` или форма с ошибкой)
- `GET /health` — health-check JSON `{"status": "ok"}`

### Переменные окружения (см. `.env.example`)

| Переменная | Назначение |
|---|---|
| `FLASK_ENV` | `development` / `production` |
| `SECRET_KEY` | секрет Flask |
| `LLM_PROVIDER` | сейчас только `ollama` |
| `LLM_BASE_URL` | по умолчанию `http://127.0.0.1:11434` |
| `LLM_MODEL` | имя модели (например `gemma3:4b`, `llama3.2:3b`) |
| `LLM_TIMEOUT` | таймаут на один блок, сек |
| `LLM_MAX_TOKENS` | лимит `num_predict` |

## Чек-листы по типовым задачам

### 1. Запустить сервис локально

```bash
# 1. Виртуальное окружение (если ещё нет)
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 2. Конфиг
cp .env.example .env   # поправь LLM_MODEL при необходимости

# 3. Ollama должна быть запущена в отдельном терминале:
ollama serve
# модель:
ollama pull gemma3:4b

# 4. Flask
python app.py          # http://127.0.0.1:5000
```

Проверка здоровья: `curl http://127.0.0.1:5000/health`.

### 2. Внести изменение

1. **Перед правкой** прочитай затронутые файлы целиком — контекст в проекте важнее скорости.
2. Соблюдай слои: схемы → сервисы → роуты → шаблоны. Бизнес-логика — в `app/services/`, валидация — в `app/models/schemas.py`, HTTP — в `app/routes.py`.
3. Новые зависимости — добавляй в `requirements.txt` и **синхронизируй** раздел «Технологии» в `README.md`.
4. Новые промпты — клади в `app/prompts/`, не хардкодь строки в сервисах.
5. Новые шаблоны наследуют стиль Organic&Natural (тёплая палитра, серифные заголовки, мягкие формы) — посмотри `app/static/css/style.css` и `app/templates/`.
6. Если меняется поведение для пользователя — обнови `README.md` (см. чек-лист ниже).
7. Если есть риск регрессии — добавь/обнови тест в `tests/`.

### 3. Обновить README.md

Держи его **коротким и точным**. Когда меняется проект, проверь и поправь:

- **Заголовок и подзаголовок** — соответствуют ли сути продукта.
- **Список «формирует»** — если появились/убрались блоки результата.
- **Раздел «Технологии»** — добавить/убрать версии и библиотеки.
- **Раздел «Структура проекта»** — дерево должно совпадать с реальной раскладкой 1-в-1. Новые файлы/папки — добавляй; удалённые — убирай. Пути и комментарии к ним — на русском, в одном стиле.
- **«Локальный запуск»** — команды `venv`, `pip install`, `cp .env.example .env`, `python app.py`. Если поменялась переменная окружения — отрази.
- **«Использование»** — пошаговый сценарий пользователя.
- **«Тесты»** — команда `pytest` (актуальна ли).
- **«Лицензия»** — только если меняется.

Не выдумывай разделы. Не пиши «Features» и «TODO» — в проекте их нет.

### 4. Проверить ошибки

1. Смотри `logger.exception(...)` в `app/routes.py:49` — туда попадают сбои LLM.
2. Типовые источники проблем:
   - Ollama не запущена → `Connection refused` на `127.0.0.1:11434`.
   - Модель не скачана → 404 от Ollama. Проверь: `ollama list`.
   - Таймаут → увеличь `LLM_TIMEOUT` в `.env` (на 7B модели 4 блока могут идти ~10–15 мин).
   - Пустой/мусорный ответ LLM — обычно валится в парсинге в `generator.py`.
3. Прогон тестов: `python -m pytest tests/ -v`.
4. Ручной смоук: `curl http://127.0.0.1:5000/health` → `{"status":"ok"}`, затем `POST /generate` через форму в браузере.

- [ ] В `README.md` актуальны разделы «Технологии», «Структура проекта», «Локальный запуск».
- [ ] `LICENSE` присутствует (в README указано MIT).
- [ ] Локально пройдены тесты: `pytest`.
- [ ] Сервис запускается с нуля по инструкции из README (проверь на чистом клоне).
- [ ] Скриншоты/демо — опционально, но лендинг-картинки в `app/static/images/` уже есть.

**Сборка релиза** (опционально): упаковка в `tar.gz`/zip без `venv/`, `__pycache__/`, `.pytest_cache/`, `.env`.

## Частые мелочи, которые нельзя забывать

- `from __future__ import annotations` — в каждом новом `.py`.
- Логирование — `logger = logging.getLogger(__name__)` на уровне модуля, не глобально.
- Ошибки LLM пробрасываются как `LLMError` (см. `app/services/llm_client.py`), в роутах ловятся и показываются пользователю с кодом 502.
- Валидация пользовательского входа — через `req.validate()` в схемах, не в роутах.
- Шаблоны Jinja2 — никакой бизнес-логики, только рендер.
- Стиль Organic&Natural в UI — единый, не плоди новых цветовых схем.
